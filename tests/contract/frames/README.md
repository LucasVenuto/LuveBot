# Observed Hermes SSE frames (T0.8)

These are raw frames captured from the REAL Hermes API Server at commit
`f8489405600c9a7d9d2f307dace086f18d7173ba` in Docker. Only the OpenAI-compatible
model provider is scripted. No Hermes event is mocked, generated by the harness
or normalized. All wire IDs and timestamps are retained.

`index.json` lists the actual field names for each captured event kind. It
contains 21 frames: 8 for `/p/default/v1/runs/{id}/events`, 13 for
`/p/default/api/sessions/{id}/chat/stream`. Each surface was exercised with one
successful tool turn and one turn stopped at a real pending approval. The first
observed frame of each kind is retained; four complete raw streams are in
`../../harness/evidence/t08/`. The suite refreshes frames when rerun.

The run stream uses `id:` plus a JSON `event` field, `timestamp` and `seq`.
The chat stream uses SSE `event:` plus `session_id`, `run_id`, `seq`, `ts`;
its approval event ALSO includes JSON `event` and `timestamp`. The stream names
and payload fields differ (`message.delta` vs `assistant.delta`, `tool` vs
`tool_name`, `message.interim` vs `assistant.commentary`). Read the frames rather
than assuming one common wire contract. A normal run did not emit `run.started`
in this observed revision; session chat did.

`approval.request` was captured on both surfaces. The test never called the
approval endpoint, stopped through the native API, read `run.cancelled`, and
verified the container-local file targeted by the command remained intact.
No unobserved event types (for example delegation or replay truncation) are
represented here. These are evidence fixtures, not the final LuveBot contract.

Reproduction commands, limits and pinned implementation links are in
`../../harness/README.md`. Actual final stdout/JUnit are under
`../../harness/evidence/t08/` (11 passed, 0 skipped, 0 failed).
